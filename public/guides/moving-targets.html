Planning waypoint interception for moving Iron Nest targets

A moving target is not always at the last grid reported by a spotter. The Waypoint planner records where a target should be at a particular game-clock time, and helps you plan the firing solution for that future location. These steps avoid mission-specific spoilers.

Record the timetable before firing

Moving-target intelligence can include an arrival station, an estimated arrival time, a rail alignment, a start position, a direction of movement or intermediate waypoints with their own timestamps. Write down the game-clock time associated with each report, not the time displayed by your phone or computer.

Open Iron Nest FCC, select Tactical Plotter and choose Waypoint. Confirm your Iron Nest position. Set an arrival/reference grid if it is known, then add waypoints in the order the target follows them.

Choose the source of each waypoint position

The planner supports four independent position methods. Calculated uses a reference point, bearing, direction and distance. Manual uses an exact grid provided by the game. Observed combines a reported grid with the report time. Relative uses another waypoint or reference plus bearing, direction and distance.

Each waypoint has its own bearing origin. One point can be measured from an arrival station, another from a named spotter, and another from a previous waypoint. The Along / Opposite direction applies independently to each report. Avoid assuming all numbers are measured from the arrival station.

Route distance versus geometric distance

The route planner distinguishes two kinds of distance:

  • Distance from a named reference places a waypoint on the map using its bearing and offset.
  • Distance remaining along the route is used with the timetable to estimate travel progress.

These are equal on some straight routes, but different when a path turns. The map draws a segment between each known waypoint; the tool interpolates between them, so a route can bend. It cannot predict an unreported detour or change in speed.

Game-clock interpolation and shell flight time

With at least two time-stamped waypoints, a target position between their timestamps can be estimated by interpolation. The position at a future impact time is what matters—not the position where a moving vehicle was spotted earlier.

The charge-and-elevation formula does not determine time of flight. The planner supports manually entered flight times, and has a separate experimental community speed model when you have no measured value. Treat estimated timing as provisional and adjust using in-game firing observations.

For example, if the target is predicted to pass a location at 10:13:30 and a measured shell takes 25 seconds to arrive, the idealized launch time is 10:13:05. This is a simple arithmetic illustration, not a verified mission schedule, and it ignores any in-game firing delay you have not measured.

Correct, save and review

Review the predicted target position and firing solution before firing. Save route inputs within the current browser session, and move a predicted intercept into Fire Solutions for the selected cannon and shell. After the shot, mark HIT or use MISS to report where the shell landed or update the target's position.

Be aware that the session-scoped IndexedDB state normally survives a page refresh, but is intended to start fresh in a new browser session; deleting the browser's site data also clears it. See the firing correction guide and the spotter triangulation guide for related workflows.
